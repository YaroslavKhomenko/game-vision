# game-vision

AI-agent skill, который помогает геймдизайнеру зафиксировать согласованную после брейншторма идею в коротком **Game Vision Document**: краткое описание, USP, Core Gameplay, Core Loop, основные правила, при необходимости — прогрессия, референсы и демо. Документ нужен, чтобы человек, не участвовавший в обсуждении, за несколько минут понял идею и смог её оценить.

Главный принцип: **фиксируем идею, а не разрабатываем игру.** Skill задаёт максимум два раунда коротких уточнений и ничего не придумывает за автора.

Работает в **Claude Code** и **Codex** — обе среды читают один и тот же `SKILL.md`, отличается только каталог установки.

---

## Установка — Claude Code

```bash
git clone https://github.com/YaroslavKhomenko/game-vision.git ~/.claude/skills/game-vision
```

Перезапусти Claude Code — skill появится как `/game-vision`.

### Обновление

```bash
cd ~/.claude/skills/game-vision && git pull
```

---

## Установка — Codex

Codex использует тот же формат `SKILL.md`, но свой каталог — `~/.codex/skills/`:

```bash
git clone https://github.com/YaroslavKhomenko/game-vision.git ~/.codex/skills/game-vision
```

Перезапусти Codex. В Codex skill вызывается через `$`: напиши `$game-vision` или выбери его в меню `/skills`. Сам по себе, без явного вызова, он не запускается.

### Обновление

```bash
cd ~/.codex/skills/game-vision && git pull
```

### Одна копия на обе среды

Чтобы не держать два клона, поставь skill в Claude Code и сделай симлинк для Codex:

```bash
git clone https://github.com/YaroslavKhomenko/game-vision.git ~/.claude/skills/game-vision
mkdir -p ~/.codex/skills
ln -s ~/.claude/skills/game-vision ~/.codex/skills/game-vision
```

Теперь `git pull` в `~/.claude/skills/game-vision` обновляет обе среды сразу.

## Использование

1. Открой в Claude Code или Codex любую папку, где хочешь хранить Vision-документы.
2. Вызови skill и сразу передай описание, заметки и решения брейншторма.

   Claude Code:

   ```
   /game-vision Игра про ... Игрок делает ... Решили, что ...
   ```

   Codex:

   ```
   $game-vision Игра про ... Игрок делает ... Решили, что ...
   ```

   Можно вызвать skill без текста — он попросит описать идею своими словами. Если присылаешь описание частями, в конце напиши, что закончил.
3. Ответь на короткие уточнения. Допустимы ответы «не определено», «не предусмотрено» и «не важно для этой идеи». Чтобы остановить вопросы, напиши: «Собери по имеющимся данным».
4. Проверь готовый Vision: верно ли описана идея и понятна ли она человеку, который не участвовал в обсуждении. Правки вноси в том же чате — skill вернёт документ целиком.

Для новой идеи начинай новый чат.

На весь этап фиксации идеи отводится максимум 2–3 часа — это предел, а не целевая длительность.

---

## Что получишь на выходе

- Vision в ответе чата — Markdown.
- Файл `<название-игры>-vision.md` в текущей папке (например, `lantern-drift-vision.md` или `untitled-game-vision.md`, если названия нет). При правках в том же чате файл перезаписывается.
- Если файл с таким именем уже лежал в папке, он не перезаписывается — новый сохраняется с суффиксом `-2`, `-3` и т. д. Путь к файлу skill пишет последней строкой ответа: `Сохранено: …`.

## Без Claude Code / Codex

Методология лежит в [`Game_Vision_Instructions.md`](Game_Vision_Instructions.md). Приложи этот файл к отдельному чату GPT или Claude и напиши: «Применяй инструкцию из файла. Помоги зафиксировать идею после брейншторма. Вот описание и принятые решения: …». Если файл не принимается, вставь его полный текст в сообщение.
